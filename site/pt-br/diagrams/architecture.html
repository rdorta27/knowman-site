ENESPT

Como as partes se encaixam

As notas entram por um vigia e uma fila de trabalhos; as perguntas voltam como citações com intervalos de linhas. Cada caixa nomeia o arquivo que a implementa.

real: sempre faz parte do sistema opcional: precisa de um modelo de linguagem seta tracejada: lê ou grava no banco de dados

Os dois fluxos

Recuperação, citações e avaliação precisam apenas de Postgres e do Ollama para os embeddings. Um modelo de linguagem acrescenta a resposta escrita em ask. Roda com Docker Compose ou de forma nativa com unidades systemd; a GPU é usada por Vulkan quando existe /dev/dri e nunca é obrigatória. As mensagens do programa, como No evidence found for that query., ficam em inglês porque são a saída literal. Fonte: core/README.md, core/docs/running.md.

Os componentes por trás deles

O mesmo sistema, agrupado por camada. Leia de cima para baixo: cada camada chama a de baixo, e a última linha é usada por todas. Cada caixa é um arquivo ou um pacote em core/src/knowman/.

A seta da esquerda vai da camada que chama para a camada da qual ela depende. Configuração, controle de acesso e registro ficam no fim porque todas as camadas acima os leem. Fonte: core/src/knowman/, core/README.md, core/docs/running.md.

Embed consultaretrieval.pyrealTransforma a pergunta em um vetor com o mesmo modelo.
Trechos próximosstore.pyrealDevolve os k trechos mais próximos (k padrão vem de RETRIEVAL_DEFAULT_K).
