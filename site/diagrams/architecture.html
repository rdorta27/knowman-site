How the parts fit

Notes go in through a watcher and a job queue; questions come back as citations with line ranges. Each box names the file that implements it.

real: always part of the system optional: needs a language model dashed arrow: reads or writes the database

Retrieval, citations and eval need only Postgres and Ollama for embeddings. A language model adds the written answer in ask. It runs under Docker Compose or natively with systemd units; a GPU is used through Vulkan when /dev/dri exists and is never required. Source: core/README.md, core/docs/running.md.

Notes (.md)CORPUS_PATH folderrealYour Markdown folder. Never modified by indexing; only the agent writes to it.
Watcherwatcher.pyrealTurns each added, edited or deleted .md file into a job.
Job queuestore.pyrealJobs are rows in Postgres: ingest_path and delete_path, with status pending, processing, done or failed.

Postgres + pgvectorstore.pyrealStores chunks, jobs, eval runs and traces. HNSW cosine index on the embedding column.
Embed queryretrieval.pyrealEmbeds the question with the same model.
Nearest chunksstore.pyrealReturns the k closest chunks (default k from RETRIEVAL_DEFAULT_K).
Distance filterretrieval.pyrealDrops chunks farther than RETRIEVAL_MAX_DISTANCE. An empty result is the explicit negative.
Citationsretrieval.pyrealEach citation carries path, line start, line end, text and distance.
LLM answerask.py, llm/*.pyoptionalOnly when LLM_PROVIDER is set (Ollama, Claude, OpenAI or Grok) and there is evidence. search and eval never need it.

Agentagent.pyoptionalknowman write: a LangGraph agent over Ollama that can search the notes and write a new one.
CLIcli.pyrealdb-init, ingest, search, ask, eval, worker, watch, mcp, write.
HTTP APIapi.pyrealSearch, ask, eval, index jobs, status; optional API_TOKEN and rate limit.
MCP servermcp_server.pyrealTwo read-only tools over stdio: search and ask.
Dashboarddashboard.pyrealOne page served at /dashboard: index vs disk, job queue, last eval, recent activity.
